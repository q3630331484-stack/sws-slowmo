# Sword With Sauce 慢动作插件（子弹时间）

给《Sword With Sauce》用的进程内时间缩放插件：**按一下热键进入慢动作，再按恢复**。
整个世界（玩家、AI、物理、投射物、动画）一起变慢，但**鼠标视角保持正常速度**——马克思·佩恩式子弹时间。倍率和热键都可以配置。

- 游戏：Sword With Sauce（Steam appid 581630，UE4.22）
- 平台：Windows 64 位
- 性质：纯单机游戏，无联机、无反作弊；插件不修改任何游戏文件，只在内存里挂钩计时函数，退出/卸载即完全恢复。

---

## 快速开始（3 步）

1. 双击 **`启动慢动作.bat`**（无控制台窗口；有问题时可用 `调试启动-带控制台.bat` 看日志）。
   - 英文界面：双击 **`Start-Slow-Mo.bat`**（出问题用 `Start-Slow-Mo-debug.bat`），英文说明见 `README_EN.md`。
2. 点 **「一键启动游戏并注入」**（游戏已经在运行就点「注入到已运行的游戏」）。
3. 进入游戏后按 **`F8`**：慢动作开；再按一次：恢复。

状态栏会显示：游戏进程、插件是否注入、慢动作开关、计时钩子实时命中次数。命中次数持续增长说明钩子工作正常。

> 第一次使用如果提示缺少 frida：双击 `安装依赖.bat`（或手动 `D:\PYTHON\python.exe -m pip install -r requirements.txt`）。

## 界面说明

| 按钮 | 作用 |
| --- | --- |
| 一键启动游戏并注入 | 没检测到游戏时先通过 Steam 启动游戏，等进程出现后自动注入 |
| 注入到已运行的游戏 | 游戏已经开着时直接注入 |
| 恢复真实时间 | 关闭慢动作，但保持注入（之后还能按热键开） |
| 卸载插件 | 移除计时钩子、断开注入。卸载前会先短暂加速把慢动作产生的“时间债”追平（1~2 秒），不会让游戏崩溃；**建议先退出游戏再卸载** |
| 状态快照 | 把当前详细状态（钩子地址、命中次数、时间频率等）打印到日志，排查问题用 |
| 应用并保存配置 | 把界面上的热键/倍率/选项写入 `config.json` 并立即对已注入的游戏生效 |

设置区：

- **热键**：可以直接输入，也可以点「捕获按键」然后按想用的键。支持 `F1`~`F24`、`A`~`Z`、`0`~`9`、方向键、`space`、`tab`、`enter`、`esc`、`mouse1`~`mouse5` 等；可加修饰键，例如 `ctrl+F8`、`ctrl+shift+F9`、`alt+mouse4`（大小写不敏感）。
- **倍率**：默认 `0.3`（三成速度）。`0.1` 很慢、`0.5` 轻微、`1.0` 等于不变。允许范围 `0.05` ~ `2.0`。
- **切换时提示音**：开关慢动作时响一声系统提示音，方便确认。
- **仅游戏窗口在前台时响应热键**：默认勾选，切出去（比如看攻略）时不会误触。取消勾选则任何时候都响应。
- 默认热键只在游戏内生效（游戏窗口在前台时），全屏/无边框窗口都支持。

## 配置文件 `config.json`

界面上的「应用并保存配置」会写入这个文件；也可以直接编辑（改完重启启动器或重新注入生效）。

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `hotkey` | `"F8"` | 热键字符串，写法见上 |
| `speed` | `0.3` | 慢动作倍率，`0.05`~`2.0` |
| `beep` | `true` | 切换时是否响提示音 |
| `require_foreground` | `true` | 是否只在游戏窗口前台时响应热键 |
| `game_path` | `D:\steam\steamapps\common\Sword With Sauce\SwordWithSauce2_4_0\Binaries\Win64\SwordWithSauce-Win64-Shipping.exe` | 游戏主程序路径 |
| `process_name` | `SwordWithSauce-Win64-Shipping.exe` | 游戏进程名 |
| `steam_appid` | `"581630"` | Steam 应用 ID，用于 `steam://rungameid/` 启动 |
| `launch_via_steam` | `true` | 点「一键启动」时是否通过 Steam 启动；改 `false` 则直接运行 exe |
| `start_timeout_sec` | `150` | 等游戏进程出现的最长秒数（Steam 首次启动/更新会久一点） |

改了 `game_path` 或游戏安装位置变化时记得同步修改，否则「一键启动」会失败（也可以手动开游戏后点「注入到已运行的游戏」）。

## 常见问题

**1. 注入失败：提示 access / permission / unable to attach**
游戏可能以管理员权限运行。两种解决办法任选：以普通权限重新打开游戏；或右键选择「以管理员身份运行」本启动器（`调试启动-带控制台.bat` 也可以）。

**2. 按热键没反应**
- 先确认游戏窗口在前台（默认「仅前台响应」）。
- 热键可能被其他软件占用，换一个（例如 `F9`、`ctrl+F8`）后点「应用并保存配置」。
- 看日志里的状态行：如果「计时钩子」次数在增长，说明插件在工作，检查倍率是否被设成了 `1.0`。
- 如果你在游戏里按了键但状态栏/日志没有「热键触发」记录，说明按键没被插件看到：确认注入成功、游戏前台，或试试把热键改成别的键。

**3. 慢动作生效了，但鼠标转视角变慢/变快？**
原理上鼠标输入是每像素增量、不乘 DeltaTime，所以应保持正常速度。若感觉有差异，多半是慢动作下准星移动的心理错觉或游戏内灵敏度设置问题，调游戏内灵敏度即可。

**4. 声音和 UI 动画也变慢了？**
正常现象：整个世界的时间都慢了，音频和 UI 动画也在同一个时间轴上。没有做音频/UI 单独复位，因为那会破坏「世界一起慢」的一致性。

**5. 极低倍率下画面抖动/物理异常？**
UE4 的物理子步进在极低时间倍率下可能不稳定。建议不要低于 `0.1`；`0.2`~`0.3` 手感最好。

**6. 游戏崩溃/卡死？**
先点「恢复真实时间」或「卸载插件」；如果已经卡死，用任务管理器结束游戏进程再重开即可。插件不写游戏文件，不会留下持久修改，重开游戏就回到原样。

**7. 游戏更新后还能用吗？**
可以。插件与 UE4 版本、pak 格式无关（它只挂钩系统计时函数）。游戏文件校验/更新不会破坏插件。

**8. 启动器报错、日志里出现 frida 相关错误**
双击 `安装依赖.bat` 重装 frida；详细错误可以看 `launcher_error.log`。同时确保游戏是 64 位 Windows 版本。

**9. 能不能同时开两个启动器 / 对同一进程注入两次？**
不能。启动器做了单实例限制；重复注入会让时间被缩放两次。请只用一个启动器窗口。

## 技术说明（给好奇的人）

- **为什么世界会一起变慢**：UE4 用 `QueryPerformanceCounter`（QPC）推导每帧 DeltaTime。插件在游戏进程内挂钩 `kernel32!QueryPerformanceCounter`，把返回的计数器按倍率缩放，于是引擎认为每帧只过了 0.3 倍的时间——玩家、AI、物理、动画、投射物全部按同一个 DeltaTime 推进，所以一起慢，而渲染帧率不变。
- **为什么只挂钩 kernel32**：Windows 里 `kernel32` 的 QPC 是个转发桩，内部跳到 `ntdll!RtlQueryPerformanceCounter`。只挂钩桩就够了；如果连 ntdll 一起挂，同一次调用会被缩放两次。实测游戏 exe 的导入表解析到的就是 kernel32 桩地址。
- **为什么开关瞬间不跳变**：虚拟时间用分段线性映射 `virtual = 锚点虚拟时间 + (真实时间 - 锚点真实时间) × 倍率`，切换倍率时以当前时刻重新设锚点，保证时间连续、单调递增，不会回跳或突进。
- **为什么鼠标视角正常**：鼠标输入是「每像素的增量」，直接改变视角角度，不乘以 DeltaTime；慢动作只影响按时间推进的东西。
- **为什么不改游戏文件 / 不用 UE4SS / 不用 Cheat Engine**：Frida 注入只改内存中的函数行为，随进程退出消失；与引擎版本和 pak 格式无关，不需要适配老版本 UE4 的 AOB。
- 真实时间用未挂钩的 `ntdll!NtQueryPerformanceCounter` 读取，避免递归。

## 回退 / 卸载

- 游戏内：先按热键关闭慢动作，再点「卸载插件」；或直接退出游戏。
- 完全不用了：把整个 `SwordWithSauce-SlowMo` 文件夹删掉即可。插件不写注册表、不改游戏目录、无后台常驻服务。
